Part 1 — The Basics

An API is a set of addresses on a server. Your app sends a request and the server returns a response (JSON). Think of it like a waiter: you order, the waiter brings the result.

Key words

WordMeaning
Base URLThe server address. Every endpoint starts with it.
EndpointA specific address + action, e.g. POST /api/registrations
GETFetch / read something. No body.
POSTCreate something new.
PUTUpdate something.
Request bodyThe JSON data sent with POST/PUT.
ResponseThe JSON returned by the server.
JSONText data as "key": "value" pairs.
Status code200 ok · 201 created · 400 bad request · 404 not found · 409 already exists · 500 server error
TokenSecret string identifying a volunteer (like a password).
OTP6-digit One-Time Password for phone login.

Base URL

EnvironmentBase URL
Productionhttps://vcc-client.vercel.app
Local devhttp://localhost:3000

What is curl?

curl is a command-line tool (built into Windows 10/11, macOS, Linux) to test API calls. On Windows open Command Prompt and type the command. Example:

curl https://vcc-client.vercel.app/api/health

Authentication

All mobile endpoints are public — no login. Admin endpoints need a JWT token sent as a header: Authorization: Bearer <token>. The mobile app never needs this.

Part 2 — Mobile Endpoints (7 calls your app needs)

1. Check the server is alive

GET /api/health

curl https://vcc-client.vercel.app/api/health
{ "status": "ok", "timestamp": "2026-08-10T05:49:57.101Z", "mongodb": "connected" }

2. Get the list of events

GET /api/events/public

Returns all events where volunteers can register or that are upcoming/ongoing.

curl https://vcc-client.vercel.app/api/events/public
{
  "events": [
    {
      "_id": "6a7717364ae497f56781ce9b",
      "name": "Sri Krishna Janmashtami 2026",
      "slug": "sri-krishna-janmashtami-2026",
      "venue": "Gadiraju convention centre",
      "registrationEnd": "2026-08-21T04:16:00.000Z",
      "eventStart": "2026-09-04T04:16:00.000Z",
      "eventEnd": "2026-09-08T04:16:00.000Z",
      "status": "registration_open",
      "coordinatorId": { "name": "chaitanya", "email": "..." }
    }
  ]
}

Show events with status: "registration_open" as "Register now". Use _id as eventId in registration.

3. Register a volunteer

POST /api/registrations  — most important endpoint

Automatically: finds the volunteer by phone (reuses existing profile if returning) → creates new profile with HKV number + seva token if new → creates the registration.

{
  "eventId": "6a7717364ae497f56781ce9b",
  "name": "Rama Das",
  "phone": "9876543210",
  "whatsappNumber": "9876543210",
  "age": 28,
  "gender": "male",
  "locality": "Dwaraka Nagar",
  "occupation": "Software Engineer",
  "skills": ["it", "photography"]
}

Required: eventId, name, phone. All else optional. Skills: medical, photography, videography, driving, electrical, sound, it, graphic_design, cooking, crowd_management, other.

curl -X POST https://vcc-client.vercel.app/api/registrations ^
  -H "Content-Type: application/json" ^
  -d "{\"eventId\":\"6a7717364ae497f56781ce9b\",\"name\":\"Rama Das\",\"phone\":\"9876543210\"}"
Tip: on Windows, put the JSON in a file body.json and use -d "@body.json" instead of escaping quotes.

Response 201:

{
  "message": "Registration successful",
  "registration": { "eventId": "...", "volunteerId": "...", "status": "registered", "_id": "..." },
  "volunteer": {
    "_id": "...",
    "name": "Rama Das",
    "volunteerNumber": "HKV-00007",
    "sevaToken": "79a741cc0505c1bc86bf478ce42788df6b64302c31fbc089523f503637f28653"
  }
}

Save the sevaToken — the app can store it to show "My Seva" without OTP.

400Registration is not open for this eventEvent not accepting registrations
400Registration deadline has passedToo late
404Event not foundWrong eventId
409Already registered for this event"You're already registered"

4. Look up a volunteer by phone (optional)

GET /api/volunteers/by-phone/:phone

curl https://vcc-client.vercel.app/api/volunteers/by-phone/9876543210

200 → { "volunteer": { ... } }  ·  404 → { "message": "Volunteer not found" }

5. Show assigned work ("My Seva")

GET /api/seva/:token

Returns the volunteer's profile + all registrations with event, assigned service, and coordinator contact.

curl https://vcc-client.vercel.app/api/seva/79a741cc0505c1bc86bf478ce42788df6b64302c31fbc089523f503637f28653
{
  "volunteer": { "name": "Rama Das", "volunteerNumber": "HKV-00007", "phone": "9876543210" },
  "registrations": [
    {
      "_id": "6a796695123edd9fb32a061b",
      "status": "registered",
      "eventId": { "name": "Sri Krishna Janmashtami 2026", "venue": "...", "status": "registration_open" },
      "serviceId": {
        "name": "Parking",
        "coordinatorId": { "name": "chaitanya", "phone": "..." }
      }
    }
  ]
}

When admin assigns work, serviceId becomes populated. 404 → { "message": "Invalid seva token" }

6. Send login OTP

POST /api/seva/send-otp

{ "phone": "9876543210" }
curl -X POST https://vcc-client.vercel.app/api/seva/send-otp ^
  -H "Content-Type: application/json" ^
  -d "{\"phone\":\"9876543210\"}"

200 → { "message": "OTP sent successfully" }
404 → no volunteer with this phone  ·  429 → wait 60 seconds

7. Verify OTP → get seva data

POST /api/seva/verify-otp

{ "phone": "9876543210", "otp": "123456" }

200 → same shape as #5. 400 → { "message": "Invalid or expired OTP" } (10-min expiry, one-time use).

Note — Status changes are admin-only

The old PUT /api/seva/:registrationId/confirm and PUT /api/seva/:registrationId/decline endpoints were removed along with the confirmed status. Volunteers can no longer change their own status — the app only reads seva data. All status transitions happen in the admin panel via PUT /api/registrations/:id/status.

registered ──▶ assigned ──▶ attended
      │              │

The app only reads these statuses. All status changes are admin-side via PUT /api/registrations/:id/status.

Part 5 — Error Handling

Errors always look like { "message": "explanation" } with an HTTP status code.

StatusWhenApp behaviour
400Bad input / invalid OTP / wrong stateShow the message
401Missing/invalid token (admin)Go to login
403Not enough permission"Not allowed"
404Not foundFriendly not-found
409Already exists"Already registered"
429Rate limited (OTP)Wait 60 seconds
500Server/database errorError screen + retry
